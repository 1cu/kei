# v0.25.2 provisional indexing patch

This patch is based on the exact v0.25.1 tag, commit
`3adb55a7cd06ae8aeb930bdbe62fa323e1aaf656`. It excludes later main changes.
It addresses the [provisional indexing proposal](https://github.com/rhoopr/kei/issues/951#issuecomment-6173266761).
Source preparation does not mean the release is published.

When Apple reports `RUNNING`, ordinary sync downloads may proceed with a warning.
The visible listing can omit photos. Kei keeps the last trusted sync token,
suppresses deletion-related state decisions from that listing, and saves a
per-library full-reconciliation requirement before downloading. Keep the state
database and existing media across restarts.

Once Apple reports `FINISHED`, kei refreshes the album plan, enumerates the full
selected scope, reuses verified downloads, and replays the retained trusted cursor
when present. It resumes incremental sync only after the normal checkpoint gates
and complete reconciliation succeed. A failed, interrupted, bounded, or uncommitted
reconciliation keeps the requirement. If the retained cursor has expired, the
existing retained-checkpoint safety hold still applies.

Managed `photos.edited_naming = "primary"` layouts wait for `FINISHED`. Provisional
coverage cannot prove safe replacement. Missing or unknown readiness responses
also stop the attempt. This patch adds no flag to bypass either guard. Configured
selection and date/recent bounds still apply and cannot be treated as proof of a
complete inventory when they truncate coverage.

The SQLite schema remains 35; the new obligation uses existing metadata rows.
A v0.25.1 downgrade does not honor this new obligation. Keep v0.25.2 and its state
until FINISHED reconciliation completes; reverting earlier can resume from a
checkpoint without enforcing recovery of provisional omissions. Follow the
[v0.25.1 matched-backup and rollback guidance](v0.25.1-upgrade.md).

This does not establish why Apple reports indexing, guarantee API completeness,
repair unrelated historical gaps, or resolve the existing sparse Shared Library
ownership limitations. Synthetic tests are not live iCloud qualification.
